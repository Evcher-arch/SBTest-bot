# Data Model: Демо-стенд ИИ-помощника

Данные разделены по владельцам. Сервисы помощника не читают хранилище заглушки
напрямую: только через её REST API.

## 1. Заглушка систем (SQLite в памяти, загрузка из `seed/`)

### Employee

| Поле | Тип | Правила |
|---|---|---|
| `id` | строка | логин, например `ivanov`; первичный ключ |
| `name` | строка | ФИО |
| `position` | строка | должность |
| `groups` | список строк | группы доступа: `all`, `sales`, `it`, `managers` |
| `manager_id` | строка или пусто | ссылка на Employee |

Производное: `subordinates` — сотрудники с `manager_id` = `id`.

Тот же файл `seed/employees.yaml` читает общий модуль `common.directory` — замена
корпоративного каталога для бота и сервиса рекомендаций. Это чтение исходного файла,
а не хранилища заглушки.

### Client (CRM)

| Поле | Тип | Правила |
|---|---|---|
| `client_id` | строка | первичный ключ |
| `name` | строка | поиск по подстроке без учёта регистра |
| `inn` | строка | 10 или 12 цифр, уникален |
| `manager_id` | строка | ответственный менеджер, ссылка на Employee |

Доступ: ответственный менеджер и его руководитель.

### Invoice (биллинг)

| Поле | Тип | Правила |
|---|---|---|
| `number` | строка | первичный ключ, например `СЧ-2026-0142` |
| `client_id` | строка | ссылка на Client |
| `date`, `due_date` | дата | в seed — смещение от текущего дня |
| `amount` | число | рубли, больше нуля |
| `status` | перечисление | `issued`, `partially_paid`, `paid`, `cancelled` |
| `payments` | список | дата и сумма каждой оплаты |

Производные: `overdue_days` = дней после `due_date`, если статус не `paid`
и не `cancelled`, иначе 0; статус для отображения `overdue` при `overdue_days` > 0.
Доступ: как у клиента счёта.

### Ticket (Service-Desk)

| Поле | Тип | Правила |
|---|---|---|
| `number` | строка | первичный ключ, например `SD-1042`; выдаётся заглушкой |
| `type_id` | строка | ссылка на TicketType |
| `title`, `description` | строка | заголовок до 200 символов |
| `fields` | объект | значения полей типа; обязательные заполнены |
| `status` | перечисление | `new`, `in_progress`, `waiting`, `resolved`, `closed` |
| `author_id`, `assignee_id` | строка | ссылки на Employee; исполнитель может быть пуст |
| `created_at`, `updated_at`, `due_at` | дата-время | `updated_at` — последнее движение |
| `history` | список | время, автор, действие |
| `idempotency_key` | строка или пусто | уникален среди заполненных |

Переходы статуса: `new` → `in_progress` → `waiting` ↔ `in_progress` → `resolved`
→ `closed`. Помощник создаёт только `new`; остальные переходы делает ведущий через
пульт. Доступ: автор, исполнитель, руководитель автора или исполнителя.

### TicketType

| Поле | Тип | Правила |
|---|---|---|
| `type_id` | строка | первичный ключ |
| `name` | строка | название для сотрудника |
| `fields` | список | `name`, `label`, `required`, `type` (`string`, `enum`, `date`), `options` |
| `sla_hours` | число | из него считается `due_at` |

### CalendarEvent

| Поле | Тип | Правила |
|---|---|---|
| `id` | строка | первичный ключ |
| `subject` | строка | тема |
| `start`, `end` | дата-время | в seed — смещение от текущего дня |
| `organizer_id` | строка | ссылка на Employee |
| `attendees` | список | сотрудники (`employee_id`) и внешние участники (`name`, `client_id`) |

Доступ: организатор и участники-сотрудники. Руководителю чужой календарь недоступен.

### Page (портал документации)

| Поле | Тип | Правила |
|---|---|---|
| `page_id` | строка | первичный ключ |
| `space` | строка | `HR`, `PROC`, `MGMT` |
| `title` | строка | заголовок |
| `body` | текст | Markdown с заголовками разделов |
| `version` | целое | растёт при каждом изменении текста |
| `updated_at` | дата-время | меняется при изменении текста |
| `allowed_groups` | список строк | группы с правом чтения |
| `acl_updated_at` | дата-время | меняется при изменении прав |

## 2. Сервисы помощника (PostgreSQL)

### chunk — фрагмент регламента (владелец: search)

| Поле | Тип | Правила |
|---|---|---|
| `id` | bigserial | первичный ключ |
| `page_id`, `page_version` | строка, целое | источник |
| `space`, `title`, `heading_path` | строка | путь заголовков через « / » |
| `url` | строка | ссылка на `/ui/pages/{page_id}` заглушки |
| `updated_at` | дата-время | дата обновления страницы |
| `text` | текст | содержимое фрагмента |
| `embedding` | vector(1536) | индекс HNSW, косинусная метрика |
| `tsv` | tsvector | конфигурация `russian`, индекс GIN |
| `allowed_groups` | text[] | индекс GIN; фильтр `&&` |

Правило: все фрагменты страницы заменяются одной транзакцией.

### index_state (владелец: search)

`page_id`, `page_version`, `acl_updated_at`, `indexed_at` — по ним индексатор
определяет, что изменилось или удалено.

### message — история диалога (владелец: orchestrator)

| Поле | Тип | Правила |
|---|---|---|
| `id` | bigserial | первичный ключ |
| `session_id` | строка | идентификатор сессии диалога |
| `employee_id` | строка | демо-сотрудник |
| `role` | перечисление | `user`, `assistant`, `tool` |
| `content` | jsonb | текст либо вызов и результат инструмента |
| `trace_id` | строка | трасса Langfuse |
| `created_at` | дата-время | |

В модель передаются последние `HISTORY_LIMIT` сообщений сессии. Токен в `content`
не попадает.

### signal — отправленный сигнал (владелец: recommender)

| Поле | Тип | Правила |
|---|---|---|
| `id` | bigserial | первичный ключ |
| `rule` | строка | `invoice_overdue`, `invoice_due_soon`, `meeting_tomorrow`, `ticket_stale` |
| `object_id` | строка | номер счёта или обращения, идентификатор встречи |
| `recipient_id` | строка | сотрудник |
| `state_key` | строка | дата состояния, чтобы новое состояние объекта дало новый сигнал |
| `text`, `url` | строка | текст и ссылка |
| `created_at`, `sent_at` | дата-время | `sent_at` пуст, пока не доставлен |

Уникальность: (`rule`, `object_id`, `recipient_id`, `state_key`).

### subscription (владелец: recommender)

`employee_id`, `rule`, `enabled` (по умолчанию включено); первичный ключ — пара
(`employee_id`, `rule`).

## 3. Короткоживущее состояние (Redis)

| Ключ | Значение | Срок |
|---|---|---|
| `role:{tg_user_id}` | `employee_id`, `session_id` | до смены роли или сброса |
| `chats:{employee_id}` | множество `tg_chat_id` для доставки уведомлений | до смены роли |
| `token:{session_id}` | JWT сотрудника | 10 минут |
| `draft:{action_id}` | черновик обращения (ниже) | 10 минут |
| `draft_result:{action_id}` | номер и ссылка созданного обращения | 24 часа |

### Draft — черновик обращения

Поля: `action_id` (UUID, он же `idempotency_key`), `session_id`, `employee_id`,
`type_id`, `type_name`, `title`, `description`, `fields`, `status`, `expires_at`,
`trace_id`.

Переходы состояния:

```text
pending ──confirm──► confirming ──успех──► confirmed
   │                     └────ошибка───► pending   (можно повторить)
   ├──cancel / смена роли──► cancelled
   └──истёк срок──────────► expired
```

Подтверждение возможно только из `pending`, только владельцем (`employee_id`
из токена совпадает с черновиком). Повторное подтверждение `confirmed` возвращает
сохранённый результат и ничего не создаёт.

## 4. Токен сотрудника (JWT, HS256)

| Поле | Содержание |
|---|---|
| `sub` | `employee_id` либо имя сервисной учётной записи |
| `name` | ФИО |
| `groups` | группы сотрудника |
| `subordinates` | идентификаторы подчинённых |
| `role` | `employee`, `recs-service` (сервисные выборки) или `indexer` (чтение страниц) |
| `exp` | не более 10 минут от выпуска |

Кто каким полям доверяет: заглушка систем использует только `sub` и `role`, а группы
и подчинённость берёт из своей таблицы Employee; поиск использует `groups` для
фильтра фрагментов; `subordinates` и `name` — справочные, решений о доступе по ним
не принимается.

## 5. Конфигурация и наборы

- **Rule** (`services/recommender/rules.yaml`): `id`, `source` (сервисная выборка
  и её параметры), `condition` (порог), `recipient` (поле с получателем),
  `schedule` (интервал), `template` (запасной текст).
- **EvalCase** (`eval/dataset.yaml`): `id`, `category` (`process`, `status`,
  `action`, `no_answer`, `foreign_data`, `injection`), `employee_id`, `question`,
  `expected_answer`, `expected_tools`, `must_contain`, `must_not_contain`,
  `must_not_create_ticket`.
