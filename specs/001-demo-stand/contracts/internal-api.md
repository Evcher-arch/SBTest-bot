# Contract: REST между сервисами помощника

Все методы — JSON поверх HTTP внутри сети compose. Ошибки — `{error: {code,
message}}` с подходящим кодом HTTP. Каждый сервис отдаёт `GET /health`.

Методы с пометкой «токен» требуют `Authorization: Bearer <JWT>`; сотрудник берётся
из токена.

## orchestrator (порт 8000)

Вызывающие: бот, сервис рекомендаций. Токен в теле запросов не передаётся:
оркестратор берёт его из Redis по `session_id`.

### `POST /chat`

Запрос: `{session_id, employee_id, text}`.

Ответ:

```json
{
  "trace_id": "…",
  "text": "Ответ помощника",
  "sources": [{"title": "…", "url": "…", "updated_at": "2026-11-02"}],
  "draft": null
}
```

Если подготовлен черновик обращения, `draft` заполнен:

```json
{
  "action_id": "uuid",
  "type_name": "Доступ и VPN",
  "title": "…",
  "description": "…",
  "fields": [{"label": "Срочность", "value": "Высокая"}],
  "expires_at": "2026-11-13T12:10:00Z"
}
```

Гарантии: ответ не позже 20 секунд; при недоступной модели — `text` с заготовленным
сообщением и код 200; `sources` формирует код из результатов поиска, а не модель.

### `POST /actions/{action_id}/confirm`

Запрос: `{session_id}`. Ответ: `{status: "confirmed", number, url, text}`.
Повторный вызов возвращает тот же `number`. Ошибки: `not_found` (черновик истёк
или не существует), `forbidden` (черновик другого сотрудника), `unavailable`
(Service-Desk недоступен; черновик остаётся `pending`).

### `POST /actions/{action_id}/cancel`

Запрос: `{session_id}`. Ответ: `{status: "cancelled"}`.

### `POST /sessions/{session_id}/reset`

Очищает историю диалога и отменяет ожидающие черновики. Вызывается при `/reset`
и смене роли.

### `POST /feedback`

Запрос: `{trace_id, value}`, где `value` — `1` или `-1`. Ответ: `{ok: true}`.
Записывает оценку к трассе; сбой Langfuse не возвращается как ошибка.

### `POST /formulate`

Вызывает сервис рекомендаций. Запрос: `{recipient_name, signals: [{rule, object,
facts, template_text, url}]}`. Ответ: `{text}` — одно сообщение на все сигналы.
Модель не получает право менять факты: числа и названия в тексте сверяются
с `facts`, при расхождении возвращается текст по шаблону.

### `POST /admin/reset`

Вызывает заглушка систем при сбросе стенда. Удаляет историю всех диалогов
и все черновики с их результатами (`draft:*`, `draft_result:*`). Ответ:
`{messages_deleted, drafts_deleted}`.

## tg_bot (порт 8443)

### `POST /notify`

Вызывает сервис рекомендаций. Запрос: `{employee_id, text, urls: []}`.
Ответ: `{delivered: <число чатов>}`. Сообщение уходит во все чаты, где сейчас
выбрана роль этого сотрудника; `delivered: 0` — не ошибка.

### `POST /admin/reset`

Вызывает заглушка систем при сбросе стенда. Удаляет выбранные роли, списки чатов
и токены (`role:*`, `chats:*`, `token:*`). Ответ: `{roles_deleted}`. После сброса
бот на любое сообщение просит выбрать роль заново.

## search (порт 8010)

### `POST /search` (токен)

Запрос: `{query, top_k}`. Ответ — как у `search_regulations` в
[agent-tools.md](agent-tools.md). Фильтр по `groups` из токена.

### `POST /admin/reindex`

Немедленный проход индексатора. Ответ: `{pages_updated, pages_deleted, chunks}`.

## recommender (порт 8030)

### `GET /signals?date=YYYY-MM-DD` (токен)

Сигналы текущего сотрудника — ответ `recs_list_my`. Правила проверяются заново
при каждом запросе; сигналы отключённых сотрудником правил не возвращаются; запрос
ничего не записывает и не рассылает.

### `PUT /subscriptions/{rule}` (токен)

Запрос: `{enabled}`. Ответ — как у `recs_set_subscription`.

### `POST /admin/run`

Немедленная проверка всех правил и рассылка. Ответ: `{signals_created,
notifications_sent}`.

### `POST /admin/reset`

Удаляет отправленные сигналы и подписки.

## Сброс стенда

Сброс — один вызов `POST /admin/reset` у заглушки систем (см.
[mock-systems-api.md](mock-systems-api.md)); она по цепочке вызывает сброс
рекомендаций, переиндексацию поиска, сброс оркестратора (история диалогов
и черновики) и сброс бота (роли, чаты, токены). Недоступность одного из сервисов
не прерывает цепочку; в ответе перечислено, что сброшено, а что нет. После сброса
каждый пользователь заново выбирает роль. Команда бота `/reset` по-прежнему очищает
историю одного диалога.
