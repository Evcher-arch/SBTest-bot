# Research: Демо-стенд ИИ-помощника

Дата: 2026-11-13. Неразрешённых вопросов (NEEDS CLARIFICATION) нет.

Версии библиотек ниже проверены поиском на дату документа; перед фиксацией в
`pyproject.toml` каждая сверяется с официальной документацией (задача этапа Setup).

## R1. Канал: Telegram-бот

- **Decision**: aiogram 3, long polling, inline-кнопки для выбора роли, подтверждения
  и оценки. Уведомления принимает встроенный в тот же процесс HTTP-метод `/notify`.
- **Rationale**: long polling не требует публичного адреса и сертификата; стенд
  поднимается на ноутбуке (принцип VIII).
- **Alternatives considered**: веб-хук (нужен публичный HTTPS); python-telegram-bot
  (равноценен, aiogram удобнее для FSM и callback-кнопок).

## R2. LLM: OpenAI, Responses API

- **Decision**: официальный OpenAI Python SDK, Responses API, вызов инструментов
  (function tools). Модель — переменная `OPENAI_MODEL`, эмбеддинги —
  `OPENAI_EMBEDDING_MODEL` (по умолчанию `text-embedding-3-small`, 1536 измерений).
  Адрес API — `OPENAI_BASE_URL` (для прокси).
- **Rationale**: OpenAI рекомендует Responses для новых проектов; у новых моделей
  вызов инструментов в Chat Completions ограничен. Имя модели не зашивается в код
  (принцип V).
- **Alternatives considered**: Chat Completions (поддерживается, но не рекомендован
  для новых проектов); OpenAI Agents SDK (скрывает цикл агента, а подтверждение
  и проверка параметров должны быть в нашем коде — принцип II).

## R3. Цикл агента

- **Decision**: собственный цикл в оркестраторе: запрос к модели → проверка имени
  инструмента по белому списку и параметров по JSON-схеме → исполнение → результат
  модели. Лимит `AGENT_MAX_STEPS` (6), таймаут вызова инструмента (8 с) и общий
  таймаут ответа (18 с). `sd_create_ticket` перехватывается: вместо вызова создаётся
  черновик, цикл завершается.
- **Rationale**: «модель предлагает, код исполняет»; около 200 строк, полностью
  тестируется с подменной моделью.
- **Alternatives considered**: LangGraph, Agents SDK — лишняя зависимость ради одного
  агента с одиннадцатью инструментами.

## R4. MCP-серверы

- **Decision**: FastMCP 3.x, транспорт Streamable HTTP, один процесс `mcp-systems`
  с пятью точками монтирования: `/crm`, `/billing`, `/sd`, `/calendar` (инструменты
  агента) и `/service` (сервисные выборки). Токен читается из заголовка
  `Authorization` через `get_http_headers(include_all=True)` — в FastMCP 3 этот
  заголовок по умолчанию скрыт. Точка `/service` отклоняет любой токен без роли
  `recs-service`; оркестратор к ней не подключается.
- **Rationale**: сервисные выборки физически отсутствуют в списке инструментов
  агента (принцип I), а не скрываются фильтром. Один контейнер вместо четырёх
  (принцип VIII), при этом границы систем сохранены точками монтирования.
- **Alternatives considered**: четыре контейнера (точнее повторяет целевую схему,
  но вчетверо больше конфигурации); общий список с проверкой роли внутри
  инструмента (выборки видны модели).

## R5. Идентификация

- **Decision**: бот выпускает JWT HS256 (`sub`, `name`, `groups`, `subordinates`,
  `role`, `exp` = 10 минут) на каждое сообщение и нажатие кнопки, кладёт в Redis
  по ключу сессии. Оркестратор получает только идентификатор сессии и достаёт токен
  в момент вызова инструмента. Один токен принимают поиск, MCP-серверы, заглушки
  и сервис рекомендаций; общий секрет `JWT_SECRET`.
- **Rationale**: сохраняет проверяемые свойства целевой схемы (сотрудник только
  из токена, токен вне промпта и трасс) без сервиса токенов.
- **Alternatives considered**: заглушка OIDC с обменом токенов (ближе к целевой
  схеме, но обмен в стенде ничего не показывает зрителю); передача идентификатора
  сотрудника заголовком без подписи (нарушает принцип I).

## R6. RAG

- **Decision**: PostgreSQL 17 с pgvector. Фрагмент хранит вектор, `tsvector`
  (конфигурация `russian`) и массив групп. Поиск: два запроса (косинусная близость
  и полнотекстовый), объединение RRF, фильтр `allowed_groups && :groups` в обоих.
  Нарезка по заголовкам Markdown, длинные разделы делятся с перекрытием. Индексатор
  раз в 60 секунд забирает страницы с изменённым `updated_at` или списком групп
  и заменяет фрагменты страницы одной транзакцией; удалённые страницы убираются
  тем же проходом по списку идентификаторов.
- **Rationale**: объём — десятки страниц; фильтр по правам обычным SQL до передачи
  модели (принцип III). Интервал 60 секунд укладывается в FR-009 (две минуты).
- **Alternatives considered**: отдельная векторная база; только векторный поиск
  (хуже находит точные термины и номера форм).

## R7. Заглушки систем

- **Decision**: один сервис `mock-systems` на FastAPI с маршрутами `/crm`,
  `/billing`, `/sd`, `/calendar`, `/confluence`, `/admin` и HTML-карточками `/ui`.
  Хранение — SQLite в памяти контейнера, загрузка из `seed/*.yaml` при старте
  и по `POST /admin/reset`. Даты в seed — смещения от текущего дня (`due: -5d`).
  Права проверяются в заглушке по JWT.
- **Rationale**: контракт инструментов раздела 5.5 сохраняется; сброс — один вызов;
  Swagger UI служит пультом ведущего (FR-028).
- **Alternatives considered**: пять отдельных сервисов; готовые мок-серверы
  (WireMock, Mockoon) — не умеют ролевую модель и изменение состояния.

## R8. Рекомендации

- **Decision**: сервис `recommender` с APScheduler; правила в `rules.yaml`
  (источник, условие, получатель, расписание, шаблон). Оценка условий — кодом.
  Ключ дедупликации: правило + объект + получатель + дата состояния. Сигналы одного
  получателя за проход объединяются в одно сообщение. Текст формулирует оркестратор
  (`/formulate`), при сбое используется шаблон правила.
- **Rationale**: принцип IV; запасной шаблон делает уведомление независимым
  от доступности модели.
- **Alternatives considered**: Celery beat (нужен брокер и воркер ради четырёх
  заданий).

## R9. Langfuse

- **Decision**: самостоятельно размещённый Langfuse v4 отдельным файлом
  `docker-compose.langfuse.yml` (официальный состав: веб, воркер, PostgreSQL,
  ClickHouse, Redis, MinIO); Python SDK v5 (требует Langfuse ≥ 4.59 и Python ≥ 3.11).
  Трасса создаётся в оркестраторе на каждое сообщение, шаги — вложенные наблюдения;
  обращения к OpenAI пишутся интеграцией SDK. `session_id` — сессия диалога,
  `user_id` — идентификатор демо-сотрудника. Оценка — score к трассе. Отправка
  фоновая; ошибки SDK перехватываются. Запасной вариант — Langfuse Cloud: меняются
  `LANGFUSE_HOST` и ключи.
- **Rationale**: единственная сквозная функция стенда; данные остаются на стенде.
- **Alternatives considered**: только Langfuse Cloud (проще, но расходится
  с принципом «внутри контура» целевой архитектуры).

## R10. Состояние и хранилища

- **Decision**: Redis — роль пользователя Telegram, токен сессии, черновик
  обращения (TTL 10 минут), результат подтверждения. PostgreSQL прикладной —
  история диалогов, индекс, отправленные сигналы, подписки. Langfuse использует свои
  экземпляры.
- **Rationale**: соответствует разделу 5.4 архитектурного решения: токен только
  в Redis и только на короткий срок.

## R11. Идемпотентность подтверждения

- **Decision**: `action_id` черновика служит `idempotency_key`. Подтверждение
  атомарно переводит черновик из `pending` в `confirming` (Redis `SET NX`),
  вызывает `sd_create_ticket`, сохраняет результат. Повторное подтверждение
  возвращает сохранённый номер. Заглушка Service-Desk дополнительно хранит ключ
  и возвращает существующее обращение.
- **Rationale**: две независимые защиты от дубля (SC-006).

## R12. Упаковка и тесты

- **Decision**: Python 3.12, uv workspace, один Docker-образ с разными командами
  запуска. Тесты — pytest, pytest-asyncio, httpx (ASGI-клиент), respx для подмены
  OpenAI и Telegram. Тесты с PostgreSQL и Redis помечены `integration` и используют
  контейнеры из compose.
- **Rationale**: один образ — одна сборка (принцип VIII); тесты не обращаются
  к внешним сервисам (конституция, процесс разработки).
- **Alternatives considered**: образ на сервис (дольше сборка, шесть Dockerfile);
  testcontainers (дополнительная зависимость при уже имеющемся compose).

## R13. Оценка качества

- **Decision**: `eval/dataset.yaml` (30–40 вопросов с ролью, категорией,
  ожиданиями) загружается в набор данных Langfuse. Скрипт прогона вызывает `/chat`
  оркестратора и проверяет: детерминированно — вызванные инструменты, наличие
  ссылки, отсутствие запрещённых строк, отсутствие созданного обращения;
  моделью-оценщиком — соответствие эталону. Категории «чужие данные»
  и «внедрённая инструкция» оцениваются только детерминированно и блокируют показ
  при любом провале.
- **Rationale**: критерии безопасности не должны зависеть от суждения модели.
