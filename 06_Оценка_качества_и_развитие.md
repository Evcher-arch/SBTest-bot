# Оценка качества и развитие

Пилот «ИИ-помощник по внутренним процессам».

## 1. Как оценивается качество

### 1.1. Тестовый набор

До запуска вместе с владельцами процессов собирается набор из 150–200 вопросов с эталонными ответами:

| Группа | Что проверяется |
|---|---|
| Вопросы о процессах | Найден нужный регламент, ответ соответствует ему, ссылка верная |
| Статусы заявок и счетов | Выбран верный инструмент и параметры, ответ совпадает с данными системы |
| Создание обращения | Верный тип и поля, действие не выполняется без подтверждения |
| Вопросы без ответа | Помощник признаёт, что не знает, и не выдумывает |
| Чужие данные | Запрос недоступных страниц, клиентов и счетов заканчивается отказом |
| Внедрение инструкций | Инструкции из текста страниц и заявок не исполняются |

Набор прогоняется автоматически перед каждым выпуском: при изменении промптов, модели, правил индексации или инструментов. Выпуск блокируется, если доля корректных ответов упала ниже порога или не прошёл хотя бы один тест из двух последних групп.

### 1.2. Метрики

| Уровень | Метрика |
|---|---|
| Поиск | Доля вопросов, для которых нужный фрагмент попал в выдачу |
| Ответ | Доля ответов, соответствующих источнику; доля ответов со ссылкой |
| Инструменты | Доля верно выбранных инструментов и параметров; доля ошибок вызова |
| Рекомендации | Доля сигналов, по которым сотрудник перешёл по ссылке; доля отключённых правил |
| Сервис | Время до начала ответа и до полного ответа; доступность |
| Использование | Активные пользователи за неделю; доля положительных оценок |

Соответствие ответа источнику на тестовом наборе проверяет модель-оценщик, а выборку её оценок регулярно перепроверяет человек.

### 1.3. Обратная связь в работе

- Оценка, трассировка и подсчёт стоимости ведутся в Langfuse, развёрнутом внутри контура. Тестовый набор тоже хранится в нём.
- Под каждым ответом в чат-боте кнопки оценки и поле для комментария; оценка прикрепляется к трассе диалога.
- На выборке диалогов модель-оценщик автоматически проверяет соответствие ответа источнику, наличие ссылки и выбор инструмента.
- Плохо оценённые диалоги раз в неделю разбирает сервисная линия. Причина относится к одной из категорий: нет регламента, регламент устарел, ошибка поиска, ошибка модели, ошибка инструмента.
- Первые две категории передаются владельцам пространств Confluence, остальные исправляются в сервисе, а сам вопрос добавляется в тестовый набор.

## 2. Этапы

| Этап | Содержание | Критерий перехода |
|---|---|---|
| 0. Подготовка | Согласование со службой ИБ, отбор пространств Confluence, сбор тестового набора, доступы к API систем | Получены согласования и доступы |
| 1. Закрытый запуск | Сервисная линия и 20–30 добровольцев; только справочные ответы и статусы | Порог качества на тестовом наборе достигнут |
| 2. Пилот | 200–500 сотрудников; все сценарии, включая создание обращений и рекомендации | Цели по метрикам пилота достигнуты, инцидентов ИБ нет |
| 3. Масштабирование | Вся компания; новые пространства, правила и источники знаний | Решение руководства по итогам пилота |

## 3. Развитие после пилота

- **Действия.** Изменение статусов обращений, действия в CRM и биллинге, по-прежнему с подтверждением.
- **Знания.** База знаний Service-Desk, остальные пространства Confluence, файловые хранилища.
- **Рекомендации.** Переход с опроса на события через брокер сообщений; конструктор правил для бизнес-подразделений.
- **Каналы.** Встраивание в интерфейсы CRM и Service-Desk.
- **Платформа.** MCP-серверы и шлюз к LLM становятся общими компонентами для других ИИ-сервисов компании; при росте индекса выделяется отдельная векторная база.

## 4. Риски проекта

| Риск | Последствие | Что делаем |
|---|---|---|
| Регламенты в Confluence устарели или противоречат друг другу | Формально верные, но бесполезные ответы; потеря доверия | Только проверенные пространства; дата обновления в ответе; обратная связь владельцам |
| У систем нет нужных методов API или обмена токенов | Сдвиг сроков, отказ от части сценариев | Проверка API на этапе подготовки; сценарии подключаются по системам независимо |
| Качество внутренней модели недостаточно для вызова инструментов | Ошибки в выборе инструментов и параметров | Ранняя проверка модели на тестовом наборе; шлюз к LLM позволяет сменить модель |
| Сотрудники не пользуются помощником | Метрики пилота не достигнуты | Канал в привычном мессенджере; проактивные рекомендации как повод вернуться; обучение на старте |
| Рекомендации воспринимаются как спам | Отключение уведомлений | Мало правил на старте; настройка подписки; контроль доли отключений |
| Согласование со службой ИБ затягивается | Сдвиг запуска | Вовлечение службы ИБ с этапа подготовки; запасной вариант по токенам для бота |
