# План выполнения тестового задания

Пилот «ИИ-помощник по внутренним процессам». Ожидаемый результат: документ на 5–15 страниц с архитектурным решением, по желанию прототип.

## Ключевые архитектурные решения

Основа решения: ИИ-агент с RAG по Confluence для справочных ответов и инструментами (tools) для работы с CRM, биллингом, Service-Desk и календарём. Поверх этой основы зафиксированы следующие решения.

1. **Рекомендации — отдельный контур.** Сервис рекомендаций с планировщиком опрашивает системы по расписанию и доставляет сигналы в мессенджер. Архитектура допускает переход на события через брокер сообщений.
2. **Сигналы формируют правила, а не LLM.** Настраиваемый каталог детерминированных правил; LLM только формулирует текст и добавляет контекст.
3. **Вызовы от имени пользователя.** Помощник не вводит собственную модель прав: инструменты обращаются к системам с токеном пользователя, RAG фильтрует фрагменты по правам на страницы Confluence.
4. **LLM внутри контура.** Внешние облачные модели не используются. Перед отправкой в LLM чувствительные поля маскируются анонимайзером.
5. **MCP как слой адаптеров.** Для каждой системы пишется свой MCP-сервер поверх её REST API, вызовы идут через API-шлюз.
6. **Изменяющие действия только с подтверждением.** В пилоте одно такое действие: создание обращения в Service-Desk. Оно выполняется после явного подтверждения пользователем.
7. **Защита от prompt injection.** Текст страниц Confluence и заявок считается недоверенными данными.

## Состав диаграммы (этап 3)

- **Канал:** чат-бот помощника в корпоративном мессенджере (включая мобильную версию).
- **Вход:** API-шлюз, аутентификация по учётной записи AD.
- **Ядро:** оркестратор агента, шлюз к LLM, анонимайзер, LLM внутри контура, Redis для сессий и токенов.
- **RAG-контур:** индексация Confluence по расписанию (Data Center, REST API), векторное хранилище, фильтр по правам.
- **Интеграции:** MCP-адаптеры к CRM, биллингу, Service-Desk и календарю Exchange.
- **Рекомендации:** каталог правил, планировщик, доставка уведомлений.
- **Сквозные функции:** журналирование с передачей в систему мониторинга событий безопасности, мониторинг инфраструктуры, Langfuse для трассировки агента, оценки качества и подсчёта стоимости.

## Состав раздела информационной безопасности (этап 5)

- утечка данных через RAG в обход прав доступа;
- prompt injection через содержимое страниц и заявок;
- избыточные права агента и изменяющие действия без подтверждения;
- персональные данные в промптах и журналах;
- выдуманные ответы и рекомендации (галлюцинации LLM).
